# 用户自助中心、套餐模板与人工续期

## 入口与使用流程

- 用户：侧栏或手机底栏的「自助中心」（`/my-sub`），查看线路配额、已用流量、到期、订阅、续期申请及服务记录。
- 管理员：「套餐与续期」（`/service-center`），包含套餐模板、批量分配、人工续期、续期申请、到期与用量提醒、操作记录。用户管理原有续期按钮也跳转到这里。
- 无在线支付、自动扣款或外部消息发送。用户提交申请后，由管理员人工确认需求，预览并执行续期，或填写不通过的回复。

## 套餐与批量分配

一个模板指定一条直连或中转线路、GB 额度、有效天数、可选限速及备注。模板可编辑、停用，有版本检查防止覆盖他人的修改。修改模板不改变已分配线路。

每批最多选择 50 人，先确认用户及套餐，再逐人提交，逐项显示成功、跳过、失败或需核对。已有相同线路或旧版协议分配的用户直接跳过，不重置订阅、额度或到期。停用、到期账号不执行新分配。

批次在浏览器中调度。离开页面或停止后，尚未提交的用户不会继续执行；已提交的操作由服务端完成并留存记录。请求连接中断不代表服务端未执行，应先查看记录，不自动重复提交。明确失败的条目可重新选择并预览。

现有系统按用户和前置机共享限速。用户在同一前置机已有其他线路时，含限速的模板会拒绝分配，避免改变其他线路的限速；可以使用不设置独立限速的模板。

## 人工续期规则

- 未到期：从原到期日顺延；已到期：从实际执行时间起算。
- 天数为 0：仅调整流量。原线路无限期时，不追加天数。
- 流量支持保持、追加、设置总额度；0 表示不单独限制线路额度。无限额线路不支持追加额度。
- 不清零已用流量，不更换订阅链接。账号状态、账号到期及账号总额度仍独立约束线路。
- 保存操作人、执行结果、内部备注、变更前后额度和到期。用户仅能查看自己的记录，内部备注不对用户显示。
- 每次提交使用唯一操作编号；同编号同参数重试返回原结果，同编号不同参数拒绝执行。数据库锁防止本模块同时修改同一用户的同一线路。

节点下发或恢复失败会标记「需核对」。不要再次增加天数来尝试修复节点；先检查当前额度、到期与节点状态，再通过原协议/转发管理核对配置。部分底层接口只返回已保存结果，最终连通性仍以实际客户端和线路诊断为准。

## 提醒和记录

站内提醒在打开或刷新页面时计算：到期前 7 天、已用流量达到 80%、流量耗尽、线路停用及账号异常。没有定时发送邮件、短信或 Telegram。

申请列表显示最多 200 条，待处理优先；执行记录每页 50 条。流量来自当前转发计数，去重同一个转发，删除或清零转发后会变化，不是长期账单流水。旧操作没有补造历史记录；本模块以外的旧管理接口修改不计入新操作记录。

## 部署与存储

前后端需一起更新。`ServiceCenterSchema` 在后端启动时使用 `CREATE TABLE IF NOT EXISTS` 新增四张表，不修改旧表的数据：

| 表 | 用途 |
| --- | --- |
| `service_plan` | 套餐模板及版本 |
| `service_action` | 执行记录、唯一操作编号、变更快照 |
| `service_operation_lock` | 同线路执行互斥 |
| `service_renewal_request` | 用户申请及管理员回复 |

数据库账号需要建表权限；若初始化失败，检查启动日志和表是否存在。四张新表应一起纳入数据库备份。

极端情况下，后端进程在操作中崩溃，记录及锁会保留为「处理中」，以避免重复续期。此时应由维护人员确认旧进程已停止、核对 `service_action` 中对应记录的前后值及实际 `inbound_line`、节点配置，记录核对结果后再修复该条记录并释放匹配的锁。不能按时间批量删除锁，也不能直接重新执行同一次续期。当前没有自动恢复或后台批次续跑。

## 验证范围

本地使用 H2 临时数据库检验 SQL、事务互斥、重复请求、配额/日期、申请归属和记录隔离；MockMvc 检验匿名、普通用户与管理员权限；包含原线路详情回归测试。H2 仅为 test 依赖，不会随生产启动连接测试库。

浏览器使用独立本地测试数据核对模板创建、批量分配、用户申请、管理员续期及记录展示。预览数据不会进入业务数据库。v1.0.0 发布流程已使用临时 MySQL 5.7 和 AMD64 前后端镜像验证启动、登录拦截及四张业务表初始化。生产库迁移、真实节点下发与客户端连通性仍需部署环境验收：先用测试账号验证一条直连和一条中转，再批量使用。
